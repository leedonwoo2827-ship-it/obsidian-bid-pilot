# 품질 가드레일 — AI Slop 방지 운영 규범

이 문서는 bid-intelligence 플러그인의 **채팅/분석 기능이 생성하는 산출물에 적용되는 규범**입니다. ChatView는 구동 시 이 파일의 "작성 원칙" 섹션을 시스템 프롬프트에 자동 주입하며, 사용자·리뷰어는 "검증 체크리스트"로 채택 전 검수합니다.

## 배경 — 왜 이 규범이 필요한가

AI Slop(AI 슬롭)은 생성형 AI가 대량 생산하는 저품질 디지털 콘텐츠입니다. Kommer 등이 제시한 세 가지 속성 — **피상적 역량**, **비대칭적 노력**, **대량 생산 가능성** — 은 수주 제안 영역에서 특히 위험합니다. 근거 없는 실적·기관명·수치가 제안서에 섞이면 심사 탈락을 넘어 신뢰 훼손으로 이어집니다.

이 플러그인은 Gemini 호출을 감싸는 유일한 레이어이므로, **모델에 전달하는 프롬프트와 모델 출력에 붙는 검수 단계 양쪽에서 AI Slop을 차단**하는 것이 목표입니다. 상세 배경은 [references/ai-slop-essay.md](references/ai-slop-essay.md)를 참고하십시오.

## 정의 — 이 플러그인이 방지하려는 AI Slop

1. **환각 인용**: 존재하지 않는 사업·기관·법령·학술 자료를 지어냄
2. **근거 없는 수치**: 예산·기간·실적·지표를 컨텍스트 없이 생성
3. **템플릿 중복**: 모든 제안서에 같은 문장 구조·같은 수식어 반복
4. **피상적 분석**: "중요하다", "고려할 필요가 있다" 같은 실행 불가 서술

## 금지 패턴

- ❌ 사용자 컨텍스트(`_context/`, pin된 노트, RAG 결과)에 없는 기관명·회사명·사업명 생성
- ❌ 구체적 금액·기간·인력 수를 근거 없이 제시
- ❌ 존재 검증 없이 "~에 따르면", "~통계에 의하면" 등 인용 수식어 사용
- ❌ 과거 제안서·실적을 근거로 "저희는 ~해왔습니다" 형태의 실적 주장 (별도 실적 컨텍스트가 제공되지 않은 경우)

## 작성 원칙 (시스템 프롬프트 자동 주입 대상)

> 아래는 ChatView가 system instruction으로 사용하는 규범입니다. 이 섹션을 수정하면 채팅 AI 행동이 즉시 바뀝니다.

- 한국어로 응답합니다.
- 제공된 컨텍스트에 없는 사실(기관명·금액·인력·법령·실적)을 지어내지 않습니다.
- 근거가 부족한 항목은 **"자료에 없음 — 확인 필요"**로 명시합니다. 추측을 사실처럼 서술하지 않습니다.
- 답변은 실행 가능한 형태로 정리합니다. "중요하다", "~할 필요가 있다" 같은 일반적 서술은 피하고, 다음 행동·책임자·기한을 구체화합니다.
- 편집 제안(`<<<EDIT ...>>>`)을 할 때는 반드시 제안된 내용 전체가 위 원칙을 충족하는지 자체 검토합니다.
- 사용자가 명시적으로 "추론해줘", "가정해줘"라고 지시할 때만 추론을 표시하며, 이 경우 **"[추정]"** 프리픽스를 붙입니다.

## 검증 체크리스트 (분석 리포트·제안서 채택 전)

사용자는 AI 산출물을 프로젝트 파일로 저장하기 전에 다음을 확인합니다.

- [ ] **기관·회사·사업명**: 언급된 모든 고유명사가 `_context/` 자료 또는 공개된 1차 자료에 실재하는가?
- [ ] **수치**: 금액·기간·인력 수·점유율 등이 출처 파일에 실제로 있는가?
- [ ] **인용 표현**: "~에 따르면"이 나오면 실제 문서·URL이 제시되는가?
- [ ] **실적 주장**: "저희가 ~했습니다" 문장이 있다면 해당 실적이 `_context/proposals/` 또는 `_context/credentials/`에 있는가?
- [ ] **추정 표시**: [추정] 또는 "자료에 없음"이 필요한 자리에 붙어 있는가?
- [ ] **중복성**: 인접 문단이 같은 말을 반복하지 않는가?

체크리스트 항목이 하나라도 실패하면 **채택 보류** — AI에 재작성을 요청하거나 수동 수정.

## 시스템 프롬프트 로드 규칙

- [ChatView](../src/views/ChatView.ts)는 `plugin.settings.systemPromptOverride`가 비어 있으면 `DEFAULT_CHAT_SYSTEM_PROMPT`를 사용합니다.
- 현재 기본 프롬프트는 이 문서의 "작성 원칙" 섹션과 동등하게 작성되어 있습니다. 이 두 곳을 변경할 때는 **양쪽을 동시에 갱신**하십시오.
- 프로젝트별 추가 규범이 필요하면 Settings → 채팅 → "시스템 프롬프트 재정의"에 덧붙입니다. 이 경우 override가 기본 프롬프트를 완전히 대체하므로, 덧붙일 때도 "작성 원칙" 전문을 포함해야 합니다.
